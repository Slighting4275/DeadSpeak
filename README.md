# DeadSpeak

DeadSpeak is a native Android fieldwork and evidence-recording app for paranormal investigations. It measures device sensors and records observations; it does not claim to prove or communicate with spirits. Sensor readings and generated words can have ordinary environmental causes, so treat them as leads to investigate rather than conclusions.

## Current features

- Native C17 Android UI using OpenGL ES 2, built with Zig's `zig cc` frontend.
- Adaptive portrait, landscape, and resizable-window layouts with shared drawing/touch geometry, scrollable evidence logs and field notes, and viewport-sized Explore pagination.
- Zig signal engine for magnetometer smoothing, field-change scoring, Goertzel audio spectrum bands, and deterministic sensor-driven word selection.
- Binary `words.bin` asset generated by the C tool at `tools/make_words.c`; the Zig engine reads and validates it at runtime. The bundled word bank contains over 5,000 unique ASCII words, including English investigation vocabulary and transliterated entries across 22 language groups. Source and licensing notes for the public-domain English list are in `tools/data/README.md`.
- Magnetometer readings when supported by the device, with unavailable hardware reported honestly.
- Native AAudio EVP recording to mono PCM16 WAV, with a live microphone level after permission is granted.
- Native Camera2 and MediaCodec video recording to MP4, using a supported camera stream up to 1920×1080 where available.
- MP4 orientation derived from the selected rear camera's sensor orientation and the display rotation at recording start, rather than a hard-coded portrait hint.
- Selectable NIGHT exposure compensation, MONO, SEPIA, and unfiltered camera modes. Camera effect modes are available only when reported as supported by the selected camera; unsupported selections report a capture error rather than silently changing modes.
- A native Explore directory sourced from Wikipedia's community-maintained reported-haunted-location categories, enriched with linked Wikidata item IDs and coordinates when available. Search and pagination work locally; each entry links to its Wikipedia article and, where available, its Wikidata item. Listings are reports, not verified claims; the directory does not upload user data.
- Persistent sensor-word log and a list of recorded evidence files in the app's private storage.

Audio and video are currently saved as separate files. Hardware support, camera stream sizes, and achieved frame rate vary by device. Explore needs an internet connection to initially download or refresh the public category index; previously cached results remain local for 30 days. Explore uses Wikipedia's public MediaWiki API for category entries and their Wikidata identifiers/coordinates. The app displays links to the source pages for attribution; Wikipedia content is available under CC BY-SA, and Wikidata data is available under CC0. Explore uses Android's platform URL/JSON classes from the native C client, with no Java app code or WebView, and does not send location, search, or account data. No paranormal app or sensor reading has been scientifically established as a means of communicating with spirits.

## Requirements

- Android SDK and NDK installed and configured for Gradle.
- Gradle 9.8.0 (checksum-verified wrapper), Android Gradle Plugin 9.4.1, JDK 17 or newer (tested with JDK 25), NDK 30.0.16248370, CMake 4.1.2, Android SDK 37.2, and build tools 37.0.0.
- The latest installed Zig compiler, including its matching standard library; C sources are compiled through `zig cc` and the signal engine is Zig. There is no alternate C engine implementation.
- Android 11 or newer, with camera and microphone hardware for recording. A magnetometer is optional.
- An internet connection for the Wikipedia/Wikidata Explore directory; sensor scanning and recording do not require it.

If Zig's standard library is outside its normal install directory, set `ZIG_LIB_DIR` to the matching Zig `lib` directory for the build.
You can also set `deadspeak.zigLibDir=/absolute/path/to/lib` in the ignored `local.properties`, or pass `-Pdeadspeak.zigLibDir=/absolute/path/to/lib` to Gradle. This setting is passed explicitly to CMake so changing the library invalidates the native build configuration. Pair libraries with the installed compiler's exact source revision. Machine-local libraries may live under the ignored `.toolchain/` directory; a `compiler-version.txt` beside `lib/` is checked against `zig version` during configuration.

## Build

Set `sdk.dir=/absolute/path/to/Android/Sdk` in `local.properties`, preserving any configured Zig library path. From the repository root, generate the binary dictionary asset and assemble the debug APK:

```sh
zig cc -std=c17 -O2 tools/make_words.c -o /tmp/deadspeak-make-words
/tmp/deadspeak-make-words
./gradlew :app:assembleDebug
```

The APK is written to `app/build/outputs/apk/debug/app-debug.apk`.

To verify the wrapper and check Android API usage:

```sh
./gradlew --version
./gradlew :app:assembleDebug :app:lintDebug --warning-mode fail
./gradlew -p build-logic test verifyAgpPatch --warning-mode fail
```

The project does not suppress deprecation warnings, and native C compilation rejects deprecated declarations. The included [build-logic patch](build-logic/README.md) removes 28 obsolete `Configuration.setVisible(false)` calls from AGP 9.4.1 and 32 from its bundled Kotlin Gradle Plugin 2.2.10. Both upstream JARs and POMs are checksum-pinned; the patch validates expected bytecode targets and generates reproducible project-local Maven dependencies. The original downloaded artifacts are unchanged. Patch verification and Java dependencies are build-time only; the app runtime remains native C/Zig. Upgrading AGP or its bundled Kotlin plugin requires reviewing this version-specific patch, or removing it once the upstream calls are gone. Patch maintenance and removal instructions are in the build-logic README.

The native application module uses AGP's supported `enableKotlin = false` setting, so it has no Kotlin compilation tasks or Kotlin standard-library runtime dependency. Gradle's Kotlin DSL and the patcher's Java code are build tooling, not app implementation.

The app uses `WindowInsetsController` through native JNI instead of the deprecated fullscreen window flag and system-bar color attributes. Modern data-extraction rules exclude app data from cloud backup and device transfer; the manifest's backup opt-out flags remain necessary for the supported Android 11 platform.

With an arm64 Android device connected, run the native C regression tests:

```sh
sh tools/test-native.sh
```

These exercise JNI thread ownership and local-reference cleanup, complete index replacement (including updated and removed pages), concurrent readers, cache persistence, responsive geometry across 900 window sizes, pagination at every supported page size, and all sixteen sensor/display orientation combinations. Explore downloads are published only after all category requests succeed; failed refreshes report failure and leave the previously saved index intact.

## Install

```sh
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n org.deadspeak/android.app.NativeActivity
```

Recordings and the word log are stored in the app's private `files/evidence` directory. Grant camera and microphone permissions when prompted. The app does not upload recordings.
